## 1. 迭代版本

### v1.1.0 —— 便携化与多设备同步稳定性迭代

本次迭代主要针对实际使用过程中暴露出的：

- 移动硬盘换电脑后盘符发生变化；
- PyCharm 无法稳定识别移动硬盘中的 PortableGit；

- 多设备环境下重复配置成本较高；

进行了系统性调整。

# 2. 迭代需求

## 2.1 核心需求

希望移动硬盘能够在不同电脑之间保持统一的工作路径。

理想状态：

```text
电脑A
G:\AI-Workspace

电脑B
H:\AI-Workspace

电脑C
I:\AI-Workspace

        ↓

统一映射

Z:\
```

使主要软件始终使用固定路径：

Z:\knowledge-base
Z:\PortableApps\Git\cmd\git.exe
Z:\PortableApps\VSCode\Code.exe
Z:\PortableApps\Obsidian\Obsidian.exe
```

从而降低不同电脑之间的环境差异。

---

## 2.2 Git 同步需求

需要解决：

```
本地仓库
    ↓
GitHub
    ↓
电脑A / 电脑B / 电脑C
```

之间的稳定同步问题。

同时要求：

- 新电脑能够正常识别移动硬盘中的 Git 仓库；
- 自动处理 Git 仓库所有权检查；
- 支持 GitHub SSH 认证；
- 避免强制覆盖远程仓库；
- 保留 Git 历史记录。

---

## 2.3 操作体验需求

希望减少批处理文件数量。

最终目标：

```
日常工作：

start.bat
    ↓
开始工作

sync.bat
    ↓
同步并结束工作
```

新电脑第一次使用时，再额外运行一次：

```
ssh-setup.bat
```

# 3. 本次迭代过程中发现的问题

## 3.1 移动硬盘盘符变化

移动硬盘在不同电脑中的盘符并不固定：

```
电脑A → G:
电脑B → H:
电脑C → I:
```

原有脚本直接依赖：

```
G:\AI-Workspace\
```

导致：

- 软件路径可能失效；
- PyCharm 中配置的 Git 路径失效；
- VSCode / Python 等工具需要重新配置。

---

## 3.2 Git 仓库所有权问题

换电脑后出现：

```
fatal: detected dubious ownership in repository
```

原因是：

```
原电脑 Windows 用户
        ↓
拥有 .git 目录

新电脑 Windows 用户
        ↓
尝试操作同一个仓库
```

Git 将其识别为不同用户之间的仓库所有权差异，因此进行了安全拦截。

通过：

```
git config --global --add safe.directory
```

将可信的 `knowledge-base` 仓库加入 Git 安全目录。

---

## 3.3 GitHub SSH 身份问题

解决仓库所有权问题后，又出现：

```
git@github.com: Permission denied (publickey)
```

进一步排查发现：

```
当前电脑
C:\Users\<username>\.ssh\
    └── known_hosts
```

只有 GitHub 主机记录，没有当前电脑对应的 SSH Key。

因此 Git 能够连接 GitHub，但无法完成用户身份认证。

最终采用：

```
每台电脑
    ↓
生成独立 SSH Key
    ↓
将公钥添加到 GitHub
    ↓
该电脑获得独立的 GitHub SSH 身份
```

---

## 3.4 批处理脚本过多

原方案存在：

```
start.bat
sync.bat
end.bat
```

随着功能增加，脚本数量继续增长会增加维护成本。

因此重新设计为：

```
start.bat
    ↓
负责启动与环境初始化

sync.bat
    ↓
负责 Git 同步 + 结束工作 + 解除虚拟盘

ssh-setup.bat
    ↓
仅用于新电脑首次 SSH 初始化
```

将日常使用流程压缩为两个脚本。

---

# 4. 解决方案

## 4.1 使用虚拟盘符统一工作路径

通过 Windows `subst` 将移动硬盘当前工作区映射到固定虚拟盘：

```
实际路径：

G:\AI-Workspace
H:\AI-Workspace
I:\AI-Workspace

        ↓

subst

        ↓

Z:\
```

以后主要软件统一使用：

```
Z:\knowledge-base
Z:\PortableApps
```

实现：

> 物理盘符变化，软件路径不变化。

---

## 4.2 start.bat 自动完成环境初始化

新的 `start.bat` 负责：

```
检测当前移动硬盘路径
        ↓
自动建立 Z: 映射
        ↓
检查 PortableGit
        ↓
检查 knowledge-base
        ↓
配置 Git safe.directory
        ↓
启动 Obsidian Portable
        ↓
启动 VSCode
        ↓
启动 Ollama
```

从而将原来的多步操作集中到一个入口。

---

## 4.3 sync.bat 统一 Git 同步与结束流程

新的 `sync.bat` 将：

```
检查仓库
    ↓
获取 GitHub 最新信息
    ↓
检查本地修改
    ↓
git add
    ↓
git commit
    ↓
git pull --rebase
    ↓
git push
    ↓
询问是否解除 Z:
```

整合到同一个流程中。

避免出现：

```
commit
pull
push
end
```

需要手工分别操作的问题。

同时避免使用：

```
git push --force
```

以降低多设备同步时误覆盖远程历史的风险。

---

## 4.4 ssh-setup.bat 自动完成新电脑 SSH 初始化

针对每台新电脑首次使用的问题，增加：

```
ssh-setup.bat
```

运行后自动：

```
检查 C:\Users\<当前用户>\.ssh\
        ↓
检查 id_ed25519
        ↓
不存在 → 自动生成
        ↓
生成 id_ed25519.pub
        ↓
自动复制公钥
        ↓
打开 GitHub SSH Key 页面
        ↓
用户手动完成一次添加
```

以后再次使用该电脑时：

```
检测到已有 SSH Key
        ↓
不重复生成
```

# 8. 学习与技术收获

## 8.1 学习了 Git 的仓库安全机制

理解了：

```
Git 仓库所有权
        ↓
safe.directory
```

认识到：

> Git 的“代码同步”不仅涉及远程仓库，还涉及本地操作系统用户与仓库文件权限。

---

## 8.2 理解了 GitHub SSH 认证机制

理解：

```
私钥
 ↓
保存在本机

公钥
 ↓
添加到 GitHub

SSH
 ↓
完成身份认证
```

并进一步认识到：

> Portable Git ≠ Portable GitHub 身份。

Git 程序可以放在移动硬盘中，但 SSH 身份通常仍然属于具体电脑上的 Windows 用户。

---

## 8.3 学习了路径抽象

通过：

```
subst Z:
```

理解了：

> 通过稳定的逻辑路径隔离物理设备路径变化。

这是一种比单纯修改脚本中的 G:/H:/I: 更工程化的解决方式。

---

## 8.4 学习了自动化脚本设计

本次迭代不再只是编写简单的 BAT 命令，而是开始考虑：

```
初始化
↓
环境检查
↓
错误处理
↓
执行核心任务
↓
结束清理
```

从单纯“能运行”逐渐转向：

> **可重复执行、可迁移、可维护的自动化流程。**

---

## 8.5 学习了 Git 多设备同步流程

重新认识：

```
commit
pull --rebase
push
```

之间的关系。

尤其认识到：

> 多设备同步不能简单理解为“把文件上传到 GitHub”，而需要考虑本地修改、远程修改、提交历史以及冲突处理。
